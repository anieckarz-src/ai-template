## Development Conventions

### Predictable Structure
Arrange files and directories in a logical layout that is easy to navigate.

### Up-to-Date Documentation
Keep README files current, including setup steps, an architecture overview, and contribution guidelines.

### Clean Version Control
Write clear commit messages, work on feature branches, and give pull requests meaningful descriptions.

### Environment Variables
Keep configuration in environment variables; never commit secrets or API keys.

### Minimal Dependencies
Keep dependencies lean and current; document the reason for including major ones.

### Consistent Reviews
Use a defined code review process with clear expectations for both reviewers and authors.

### Testing Standards
Set the required test coverage (unit, integration, etc.) that must be met before merging.

### Feature Flags
Put incomplete features behind flags rather than keeping long-lived branches.

### Changelog Updates
Keep a changelog or release notes for significant changes.

### Build What's Needed
Don't write speculative code or "just in case" additions (see minimal-implementation.md).
