## Coding Style

### Naming Consistency
Stick to the project's established naming patterns for variables, functions, classes, and files.

### Automatic Formatting
Rely on automated tools to keep indentation, spacing, and line breaks consistent.

### Descriptive Names
Pick names that make intent clear; outside tight loops, avoid cryptic abbreviations and single-letter identifiers.

### Focused Functions
Have each function do one thing well; smaller functions are easier to read, test, and maintain.

### Uniform Indentation
Settle on either spaces or tabs and enforce the choice through editor/linter settings.

### No Dead Code
Delete unused imports, commented-out blocks, and orphaned functions rather than leaving them in place.

### No Backward Compatibility Unless Required
Don't add extra code paths for backward compatibility unless they are explicitly needed.

### DRY (Don't Repeat Yourself)
Pull repeated logic out into reusable functions or modules.
